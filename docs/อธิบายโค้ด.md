# อธิบายโค้ด (อ่านเตรียมตอบอาจารย์)

## 1. ภาพรวมใน 1 นาที

โปรเจกต์นี้มี **2 ภาษา**
- **Python** = ตัวเครื่อง (CPU จำลอง) อยู่ใน `main.py`, `cpu.py`, `isa.py`, `memory.py`
- **MIPS assembly** = โปรแกรมที่ป้อนเข้าเครื่อง อยู่ใน `programs/*.asm`

เหมือนโปรแกรมจำลองเครื่องเล่นเกม (Python) กับตัวเกม (MIPS)

เส้นทางของโปรแกรม 1 ไฟล์:
```text
nck.asm (ตัวหนังสือ)
   │  isa.assemble()  แปลงเป็นตัวเลข 2-pass
   ▼
machine code 32 บิต  ──►  เขียนลง memory (stored program)
   │
   ▼  cpu.run(): วน fetch → decode → execute จนเจอ HALT / SYSCALL 10
ผลลัพธ์ที่พิมพ์ด้วย SYSCALL 1
```

## 2. แต่ละไฟล์ทำอะไร

### memory.py (RAM)
- เก็บข้อมูลทีละ **byte** ใน dictionary `{address: ค่า}` ที่อยู่ที่ไม่เคยเขียนถือว่าเป็น 0
- `read_word` / `write_word` อ่าน/เขียนทีละ 4 byte แบบ **Big Endian** (byte สำคัญที่สุดอยู่ address ต่ำสุด เหมือน CPU COE/MIPS-32 ในแบบฝึกหัดครั้งที่ 1)
- address ของ word ต้องหารด้วย 4 ลงตัว ไม่งั้นแจ้ง error

### isa.py (ตัวแปลภาษา)
- **`assemble()`** แปลง assembly เป็น machine code แบบ **2-pass**
  - **pass 1:** อ่านทีละบรรทัด ตัด comment เก็บ label แล้วนับที่อยู่ (คำสั่งละ 4 byte, `.ORG` เปลี่ยนที่อยู่ได้)
  - **pass 2:** แปลงแต่ละคำสั่งเป็นตัวเลข ตอนนี้รู้ที่อยู่ของทุก label แล้ว จึงคำนวณระยะ branch ได้
  - ต้องมี 2 รอบ เพราะคำสั่งอาจกระโดดไป label ที่อยู่**ข้างล่าง** ซึ่งรอบแรกยังไม่รู้ที่อยู่
- **`decode()`** ทำกลับกัน: แยกตัวเลข 32 บิตเป็นช่อง opcode, rs, rt, rd, shamt, funct, immediate
- รับได้ทั้งแบบโค้ดอาจารย์ (`ORI $2 $0 10`, `BNE $0 $2 -3`) และแบบ MARS (`bne $v0, $zero, loop`)

### cpu.py (CPU)
- `registers[0..31]`, `PC`, และ `EPC`, `Cause` สำหรับ exception
- **`step()`** ทำ 1 คำสั่ง: fetch (อ่าน word ที่ PC) → decode → execute
- **`execute()`** มีโค้ดของแต่ละคำสั่ง เช่น `add` บวกแล้วเช็ก overflow, `lw` อ่านหน่วยความจำ, `beq` เปลี่ยน PC
- **`syscall()`** 1 พิมพ์ตัวเลข, 5 อ่านตัวเลข, 10 จบ, 11 พิมพ์ตัวอักษร
- **`raise_exception()`** ตามเอกสารบท 4.2.1: เก็บ EPC, ตั้ง Cause แล้วไปที่ 0xC0000000

### main.py (ปุ่มเปิดเครื่อง)
- อ่านชื่อไฟล์และตัวเลือก (`-q`, `-t`, `-s`, `-l`, `-d`, `--stats`) สร้าง Memory กับ CPU แล้วสั่งรัน
- จัดการ input ของ SYSCALL 5 (พิมพ์ `5 2` บรรทัดเดียว หรือทีละบรรทัดก็ได้) และแสดงสรุปผล

## 3. ตัวอย่างแปลงคำสั่งเป็น machine code (ทำมือได้แบบในแบบฝึกหัด)

**R-type:** `add $t5, $t5, $t6` → rd = 13, rs = 13, rt = 14, funct = 0x20
```text
opcode  rs     rt     rd     shamt  funct
000000  01101  01110  01101  00000  100000   = 0x01AE6820
```

**I-type:** `lw $t6, -4($t4)` → opcode = 0x23, rs = 12, rt = 14, imm = -4 = 0xFFFC
```text
opcode  rs     rt     immediate
100011  01100  01110  1111111111111100       = 0x8D8EFFFC
```

**Branch:** `beq $t3, $zero, nexti` อยู่ที่ 0x000000A8, nexti อยู่ที่ 0x000000CC
```text
offset = (ที่อยู่ปลายทาง − (PC + 4)) ÷ 4 = (0xCC − 0xAC) ÷ 4 = 8   → 0x11600008
```
ตอนรัน CPU คิดกลับ: PC ใหม่ = PC + 4 + offset × 4

**Jump:** `j loopj` (loopj อยู่ที่ 0xA8) → เก็บ 0xA8 ÷ 4 = 0x2A ในช่อง address → `0x0800002A`

ดูตารางของทั้งโปรแกรมได้ด้วย `python main.py -l programs/nck.asm`

## 4. โปรแกรม factorial.asm

```text
main: อ่าน n → ถ้า n < 0 พิมพ์ -1 → jal fact → พิมพ์ผล → จบ
fact(n):
    จอง stack 8 byte, เก็บ $ra และ n
    ถ้า n < 2: คืน 1
    ไม่งั้น: fact(n-1) แล้ว mul(ผลนั้น, n)
    คืนค่า $ra, คืน stack, jr $ra
mul(a, b): v0 = 0 แล้วบวก a ซ้ำ b ครั้ง
```

**ทำไมต้องใช้ stack:** `jal` เขียนที่อยู่กลับลง `$ra` ทุกครั้ง ถ้า fact เรียกตัวเองโดยไม่เก็บ `$ra` เดิมไว้ จะกลับไปหา main ไม่ถูก และ n ใน `$a0` ก็ถูกเปลี่ยนตอนเรียกซ้อน จึงต้องเก็บทั้งสองค่าไว้ในหน่วยความจำ (stack) ซึ่งอาจารย์บอกไว้ในห้องว่า "เพิ่ม JAL ต้องเขียน STACK เพิ่ม"

ลองดูได้ด้วย `python main.py -t programs/factorial.asm` (ใส่ 4) จะเห็น `$sp` ลดลงทีละ 8 ตอนเรียกซ้อน และเพิ่มกลับตอนคืนค่า

## 5. โปรแกรม nck.asm

```text
main: อ่าน n, k → ตรวจ 0 ≤ k ≤ n ≤ 33 (ไม่ผ่านพิมพ์ -1) → jal nck → พิมพ์ผล
nck(n, k):
    C = array ที่ 0x10010000, C[0] = 1, C[1..k] = 0
    for i = 1..n:
        for j = min(i, k) ลงไปถึง 1:
            C[j] = C[j] + C[j-1]
    return C[k]
```

ตัวอย่าง 4C2 (เก็บแค่ C[0..2]):

| หลังแถว i | C[0] | C[1] | C[2] |
|---|---|---|---|
| เริ่ม | 1 | 0 | 0 |
| 1 | 1 | 1 | 0 |
| 2 | 1 | 2 | 1 |
| 3 | 1 | 3 | 3 |
| 4 | 1 | 4 | **6** |

**ทำไมไล่ j จากมากไปน้อย:** ถ้าไล่จากน้อยไปมาก C[j-1] จะเป็นค่าของแถวใหม่ไปแล้ว ผลจะผิด การไล่ถอยหลังทำให้ใช้ array แถวเดียวได้

**ทำไมใช้ `sll $t4, $t3, 2`:** ที่อยู่ของ C[j] = ฐาน + j × 4 และการคูณ 4 คือการเลื่อนบิตไปทางซ้าย 2 บิต จึงไม่ต้องใช้คำสั่งคูณ

## 6. เรื่องเล่าตอนนำเสนอ (4 จังหวะ)

1. **ทำได้:** factorial 5 = 120 และใช้ฟังก์ชันคูณที่เขียนเอง (บวกซ้ำ) เรียกด้วย jal พร้อม stack
2. **พัง (เดโมสด):** ใส่ 13 → `Exception: Arithmetic overflow` เพราะ register มี 32 บิต เก็บได้สูงสุด 2,147,483,647 แต่ 13! = 6,227,020,800
3. **อธิบายสาเหตุ:** ถ้าคิด nCk ผ่าน factorial จะใช้ได้แค่ n ≤ 12 แต่อาจารย์ต้องการถึง 26 (26! มี 27 หลัก)
4. **แก้:** เปลี่ยนเป็นสามเหลี่ยมปาสคาล ใช้แค่การบวก ตัวเลขไม่เคยใหญ่เกินคำตอบ → 26C13 = 10,400,600 และทดสอบทุกค่า 633/633 ผ่าน

ข้อสรุปที่อยากให้อาจารย์ได้ยิน: **ฮาร์ดแวร์มีขีดจำกัด (32 บิต) โปรแกรมเมอร์ต้องเลือกอัลกอริทึมให้เหมาะกับฮาร์ดแวร์**

## 7. คำถามที่อาจารย์น่าจะถาม

**ถาม: simulator ของเรารันจากอะไร ตัวหนังสือหรือ machine code?**
ตอบ: จาก machine code ในหน่วยความจำ assembler แปลงเป็นตัวเลขแล้วเขียนลง memory ก่อน แล้ว CPU fetch ทีละ word มา decode เหมือน CPU จริง (stored program)

**ถาม: ทำไม assembler ต้อง 2-pass?**
ตอบ: เพราะ branch/jump อาจไป label ที่อยู่ข้างล่าง รอบแรกยังไม่รู้ที่อยู่ รอบแรกจึงเก็บที่อยู่ของ label ทั้งหมดก่อน รอบสองค่อยแปลง

**ถาม: add กับ addu ต่างกันยังไง?**
ตอบ: ผลบวกเหมือนกัน แต่ add ตรวจ overflow ถ้าเกิดจะเกิด exception ส่วน addu ไม่ตรวจ (green card หมายเหตุ 1) เราใช้ add ในฟังก์ชันคูณ จึงจับได้ว่า 13! ล้น

**ถาม: overflow ตรวจยังไง?**
ตอบ: แปลงเป็นเลขมีเครื่องหมายแล้วบวกด้วย Python ถ้าผลมากกว่า 2^31 − 1 หรือน้อยกว่า −2^31 แปลว่าล้น ซึ่งเทียบเท่ากับกฎ "บวก+บวกได้ลบ หรือ ลบ+ลบได้บวก"

**ถาม: เกิด exception แล้ว CPU ทำอะไร?**
ตอบ: ตามเอกสารบท 4.2.1 เก็บที่อยู่คำสั่งที่ผิดใน EPC, ตั้ง Cause (1 = overflow, 0 = undefined instruction) แล้วไปที่ handler 0xC0000000 ถ้าไม่มี handler จะหยุดและแจ้ง ดูตัวอย่าง handler ได้ที่ `examples/overflow_demo.asm`

**ถาม: $zero ถูกเขียนได้ไหม?**
ตอบ: ไม่ได้ `set_reg()` ไม่ยอมเขียน register 0 จึงเป็น 0 เสมอ

**ถาม: jal กับ jr ทำงานยังไง?**
ตอบ: jal เก็บ PC + 4 ลง $ra แล้วกระโดด, jr $ra กระโดดกลับไปที่อยู่ใน $ra (ของเราไม่มี delay slot จึงเก็บ PC + 4 ไม่ใช่ PC + 8 แบบ green card)

**ถาม: ทำไม nCk ได้ถึงแค่ 33?**
ตอบ: 34C17 = 2,333,606,220 เกิน 2,147,483,647 ถ้าจะไปต่อต้องเก็บตัวเลขใหญ่ด้วย register หลายตัว ซึ่งเกินขอบเขตโปรเจกต์ (อาจารย์ต้องการถึง 26)

**ถาม: พิสูจน์ได้ยังไงว่าถูก?**
ตอบ: `tests/run_tests.py` รันทุกคู่ 0 ≤ k ≤ n ≤ 33 (595 คู่) เทียบกับ `math.comb` ของ Python, factorial 0..12 เทียบกับ `math.factorial`, กรณี input ผิด, โค้ดรูปแบบอาจารย์ และเรียกผ่าน command line จริง ผ่านทั้งหมด 633/633

**ถาม: ถ้า multi-cycle จะใช้กี่ clock?**
ตอบ: `python main.py --stats programs/nck.asm` นับจำนวนแต่ละคำสั่งแล้วคูณจำนวน clock ตามตาราง 4.22 (lw 5, sw 4, R-type 4, beq/j 3) เช่น 26C13 ใช้ 2,671 คำสั่ง: single-cycle 2,671 clock, multi-cycle ประมาณ 10,548 clock (CPI ≈ 3.95) แต่ clock ของ multi-cycle สั้นกว่า
